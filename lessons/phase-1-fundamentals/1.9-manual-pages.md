# 1.9 — Manual Pages & Finding Help

## What I learned

Every standard Linux command has built-in documentation, no internet required:
```bash
man ls          # full manual
ls --help       # quick flag summary
whatis ls       # one-line description
```
Inside `man`: scroll with arrows/Space, quit with `q` (same convention as `top`), search with `/term` then `n` for next match.

**Real gotcha found in `man ps`:** `ps aux` (no dash, BSD-style) and `ps -aux` (with dash, POSIX-style) look nearly identical but mean different things. `-aux` technically means "show all processes plus any owned by a user literally named x" — `ps` just silently falls back to the BSD interpretation since no such user usually exists, masking the mistake. Correct habit: always `ps aux`, never `ps -aux`.

**Bigger lesson:** command-line tools often silently tolerate technically-incorrect syntax, which can build habits that "work" for years until a different system/distro/container doesn't forgive the same mistake. Worth being precise now, especially before writing scripts meant to run identically across many machines.
