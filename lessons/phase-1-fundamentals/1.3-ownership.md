# 1.3 — Ownership (chown)

## What I learned

Every file has an owner (user) and a group. `chown` changes who those are — separate from `chmod`, which controls what actions are allowed.

I tested this directly: ran `sudo chown root:root ownership-test.txt` on a file I created. The permission bits never changed (`644` the whole time) — but I could no longer edit it in VS Code, because I was no longer the owner or in the owning group, so I only had "others" access (`r--`, read-only). Permissions only mean something in combination with ownership — the same `644` means something different depending on who's asking.

`chown` requires `sudo` because reassigning ownership is more sensitive than adjusting permissions on something I already own — it prevents users from freely handing files to other identities.
