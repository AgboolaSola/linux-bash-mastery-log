# 1.7 — System Services & systemd

## What I learned

`systemd` is the init system — the first process to start on boot (PID 1), responsible for starting, stopping, monitoring, and auto-restarting every other background service ("service" = a program meant to run continuously, like a web server or database).

Analogy: systemd is like a building manager — doesn't do the work itself, but makes sure every service starts up, stays running, and gets restarted if it fails.

```bash
systemctl status <service>
systemctl start/stop/restart <service>
systemctl enable <service>   # auto-start on boot
```

Tested with `systemctl status cron` — confirmed `Main PID: 117` matched the exact same PID I'd already seen in `ps aux` earlier, proving `systemctl` and `ps aux` are just two different windows into the same real running process.

**Why this matters over a bare `&` background process:** a process backgrounded with `&` dies when its terminal session ends. A systemd-managed service survives independent of any login session, and restarts automatically if it crashes — the actual gap that `&` doesn't solve.

## cron
`cron` itself is the always-running daemon that checks a schedule (crontab) and executes whatever's configured, at the configured time — it doesn't inherently "do" anything on its own beyond reading and enforcing that schedule. My server's cron runs `/etc/cron.hourly` jobs every hour.
