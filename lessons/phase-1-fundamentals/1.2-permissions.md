# 1.2 — Permissions (chmod)

## What I learned

Every file/folder has three permission sets: owner, group, others. Each can have read (r), write (w), execute (x).
- Symbolic form: `rwxr-xr-x`
- Numeric form: r=4, w=2, x=1, added per audience (e.g. `755` = owner rwx, group r-x, others r-x)
- Common values: `755` (scripts/directories), `644` (regular files), `600` (private/sensitive files like secrets)

**Directory permissions are NOT the same as file permissions**
- `x` on a directory = permission to enter/traverse it, not read its contents
- `r` on a directory = permission to list what's inside it
- `w` on a directory = permission to add, delete, or rename entries inside it — NOT permission to edit file contents

I proved this with an experiment: created a folder with `chmod 000`, put a file inside it, and even though the file itself had full `777` permissions, I couldn't read it — because I had no `x` on the parent folder to even reach it.

I also proved the reverse: a file with `chmod 000` (unreadable, unwritable) can still be **deleted** by anyone with `w` on the parent directory — because deleting is a directory-level operation, not a file-level one. This surprised me — I assumed locking a file down fully would protect it from deletion too.

## Mistakes / surprises
- Assumed `chmod 000` on a file alone would fully protect it — learned directory-level `w` can still allow deletion
- Assumed running a script required write permission — actually only needs read + execute (least privilege)
