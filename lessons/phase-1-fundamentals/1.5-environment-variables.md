# 1.5 — Environment Variables

## What I learned

An environment variable is a named value stored in memory that programs can read to change their behavior. `~` itself works because of an environment variable called `HOME`.

```bash
echo $HOME              # view a variable's value
export MY_VAR="hello"   # create one, available to child processes
env | grep MY_VAR       # confirm it's in the exported table
```

`export` matters because a variable set without it only exists in the current shell — child processes/scripts launched from that shell won't see it. `echo $VAR` alone doesn't prove export worked (it shows the same result either way); checking `env | grep VAR` is the real proof, since `env` only lists what's actually inheritable by child processes.

## Why this matters
Environment variables are the standard way to configure software without hardcoding secrets (like DB passwords, API keys) directly into code. Critical in Docker and CI/CD later — containers and pipelines are configured almost entirely this way.

## Mistakes / surprises
- Forgetting `export` is a common bug source — the variable "exists" but is invisible to anything you launch from that shell
