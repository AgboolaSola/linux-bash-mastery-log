# 4.6 — Functions

## What I learned

```bash
function_name() {
    commands
}
function_name    # call it
```

**Parameters:**
```bash
greet() {
    local name=$1
    echo "Hello, $name!"
}
greet "Sola"
```
`$1` = first argument passed to the function, `$2` = second, and so on. `local` restricts a variable to only exist inside that function — doesn't leak into the rest of the script. Opposite direction from `export` (which expands visibility to child processes) — `local` narrows it.

## Real example: reusable file-check function
Turned a one-off `if [ -f ... ]` check into a reusable function:
```bash
check_archive() {
    local file_path=$1
    if [ -f "$file_path" ]; then
        echo "✓ Archive exists: $file_path"
    else
        echo "✗ Missing archive: $file_path"
    fi
}
check_archive "$HOME/path/to/real-file.tar.gz"
check_archive "$HOME/path/to/fake-file.tar.gz"
```
Confirmed correctly reporting one real archive as found, one fake path as missing — callable with any path, no repeated code.

## Two-parameter function, mirroring cp/mv
```bash
backup_file() {
    local source=$1
    local destination=$2
    if [ -f "$source" ]; then
        cp "$source" "$destination"
        echo "Backed up $source to $destination"
    else
        echo "Cannot back up — $source does not exist"
    fi
}
backup_file "$HOME/path/README.md" "$HOME/path/README-backup.md"
```
Confirmed the backup file was created correctly with the exact original content. Wraps `cp`'s source/destination pattern with a safety check `cp` itself doesn't have — won't attempt the copy at all if the source is missing.
