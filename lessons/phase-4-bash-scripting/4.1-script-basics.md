# 4.1 — Script Basics

## What I learned

A Bash script is a plain text file of commands, run all at once in order.

```bash
#!/bin/bash
```
Must be the very first line (the "shebang") — tells the system to run this file using Bash specifically, rather than guessing based on default shell.

**Permission gotcha:** `touch` creates files without execute permission by default. Tried running `./hello.sh` immediately after creating it and got `Permission denied` — fixed with `chmod 700 hello.sh` (owner: full rwx, nothing for group/others, since this is a personal script only I need to run).

**Why `./` is required:** Bash only auto-searches folders listed in `$PATH` (echo `$PATH` to see them — this is literally where `ls`, `git` etc. live as real files, e.g. `/usr/bin`). My script's folder isn't in `$PATH`, so plain `hello.sh` would fail with "command not found" — `./` explicitly says "look in the current directory instead." Professional scripts often get moved into a `$PATH` folder once finished, so they can be run from anywhere by name alone (Phase 6 territory).
