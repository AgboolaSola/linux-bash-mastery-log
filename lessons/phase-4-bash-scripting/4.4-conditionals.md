# 4.4 — Conditionals (if / elif / else)

## What I learned

```bash
if [ condition ]; then
    # ...
elif [ another_condition ]; then
    # ...
else
    # ...
fi
```

Strict whitespace rules (same family as `=` in variable assignment and `alias`):
- Must have a space right after `[` and right before `]` — `[condition]` breaks it
- Block must close with `fi`, not `endif` or `}`

## Comparison operators
```bash
[ "$a" == "$b" ]   # string equal
[ "$a" != "$b" ]   # string not equal
[ "$a" -eq "$b" ]   # number equal
[ "$a" -gt "$b" ]   # number greater than
[ "$a" -lt "$b" ]   # number less than
[ -f "$file" ]      # true if $file exists AND is a regular file
[ -d "$dir" ]       # true if $dir exists AND is a directory
```
`==`/`!=` for strings, `-eq`/`-gt`/`-lt` (words, not symbols) for numbers — easy to mix up.

Built and tested a number-comparison script (`if/elif/else` with `-gt`/`-eq`) — confirmed all three branches work correctly with real input (10, 2, 40).

## Real bug I hit: stale hardcoded path
Added a file-existence check (`[ -f "$archive_file" ]`) before allowing cleanup — modeled directly on the Phase 3 assessment's manual "verify archive before deleting" step. The check kept failing ("not found") even though the archive genuinely existed. Root cause: the path was written *before* `app-server/` got moved into the repo during Phase 3's commit fix — the script was checking a now-stale location. The `-f` logic itself was completely correct; it just told the truth about the wrong path. Real lesson: hardcoded paths silently go stale the moment something gets reorganized, and a script fails "correctly" while the actual mistake is upstream.

## -f vs -d: not interchangeable
`-f` checks "is this a regular file," `-d` checks "is this a directory" — genuinely different questions, not two versions of "does this exist." Using the wrong one doesn't always error loudly — often it just makes a safety check silently useless (e.g. checking `-f` on what's actually a directory always returns false, potentially causing a script to wrongly assume something doesn't exist and proceed unsafely). More dangerous than a crash, because the check *looks* protective while checking the wrong thing entirely.
