# 4.8 — Capstone: log-cleanup.sh

## What I built

A complete, reusable Bash script combining every concept from Phase 4:
variables, conditionals, loops (via find), functions-equivalent logic,
script arguments with a `read` fallback, and exit codes.

**Behavior:**
1. Accepts a target folder as `$1`, or asks interactively via `read -p` if omitted (`-z` check)
2. Verifies the folder exists (`-d`), exits 1 if not
3. Counts `.log` files via `find | wc -l`; exits 0 cleanly if none found (not a failure — nothing to do)
4. Archives all logs into a date+time-stamped `.tar.gz` (avoids overwriting same-day archives)
5. Verifies the archive actually exists AND is non-empty (`-f` + `-s`, combined with `&&`) before doing anything destructive
6. Only after verification, deletes the original `.log` files with `find ... -delete` (never `rm -rf` — that would delete the whole folder indiscriminately, not just the target files)
7. Prints a summary: number of files archived, archive filename

## Real bugs caught along the way
- Forgot `exit 1` initially on the "folder doesn't exist" branch — script kept running and returned exit code 0 even on failure, since a script that completes without an explicit `exit` defaults to success. Exit code reflects whether the script *ran to completion*, not whether the outcome was actually good.
- Forgot to save the file in VS Code before testing — tested stale code and got confusing results. Now habitually `cat` the file to confirm what's actually saved before running it.
- Considered `rm -rf "$foldername"` for cleanup — caught myself: that would delete the entire folder and anything else in it, not just the `.log` files. Used `find "$foldername" -name "*.log" -delete` instead — surgical, only touches matching files.

## Tested end-to-end
- Ran against a folder with 3 real log files — archived, verified, deleted, summary printed correctly
- Ran again against the now-empty folder — correctly detected zero logs, exited 0, no false failure
