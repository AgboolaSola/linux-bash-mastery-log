# 3.3 — Log Rotation (logrotate)

## What I learned

Without rotation, a busy server's logs can grow unbounded and eventually fill the disk completely — a real, common cause of production incidents. `logrotate` is Ubuntu's built-in tool for automatically rotating logs on a schedule (via cron), instead of engineers doing it manually.

Read the real system config at `/etc/logrotate.conf`:

weekly # HOW OFTEN rotation happens
rotate 4 # HOW MANY old copies to keep before deleting the oldest
create # immediately create a fresh empty log after rotating, so the service doesn't error writing to a missing file
su root adm # rotated logs owned by root/group adm — ties back to Phase 1 ownership concepts
#compress # commented out = disabled by default; would gzip old logs automatically if uncommented

**Initially misread `weekly` + `rotate 4` as "rotates every 4 weeks"** — corrected: it rotates every week, and keeps the last 4 weekly copies at any time (~1 month of bounded history). Once a 5th rotation happens, the oldest of the 4 kept copies is permanently deleted to make room — automatic, capped history, no manual cleanup ever needed.
