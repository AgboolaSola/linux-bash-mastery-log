# 2.4 — cut, sort, uniq

## cut
Extracts specific fields/columns using a delimiter.
```bash
cut -d':' -f1 /etc/passwd   # usernames
cut -d':' -f6 /etc/passwd   # home directories
```
Works great on `/etc/passwd` because it uses a single, fixed colon delimiter every time. Fails on `ps aux` output because that uses a *variable* number of spaces for visual alignment — `cut` treats every delimiter character as a new field boundary, so padding throws off field numbering. `awk` handles variable whitespace correctly (treats any number of consecutive spaces as one separator) — that's why `awk '{print $1}'` was the right tool for `ps aux`, not `cut`.

Noticed several system service accounts (`nobody`, `messagebus`, `systemd-network`) have `/nonexistent` or `/` as home directories — these are non-human service accounts, each running under their own restricted user rather than root, a real example of least privilege at the OS level.

## sort
```bash
sort filename       # alphabetical
sort -n filename     # numeric (without -n, "10" sorts before "2" — string comparison, not magnitude)
sort -r filename     # reverse
```

## uniq
Removes only **consecutive** duplicate lines — has no memory beyond the immediately previous line. Input must be sorted first, or duplicates that aren't adjacent won't be caught at all.
```bash
sort filename | uniq
sort filename | uniq -c   # count occurrences
```

**Gotcha:** ran `ps aux | awk '{print $1}' | sort | uniq -c | sort -rn` to rank users by process count — result included a fake "user" called `USER`, which was actually just `ps aux`'s own header row getting swept into the pipeline. Real command output almost always includes header/label lines that aren't actual data. Fixed with `grep -v USER` before the rest of the pipeline — same tool, same "exclude this one thing" pattern as filtering grep's self-match back in Phase 1.

**Also learned:** `sort -r` (no `-n`) happened to still produce correct-looking numeric order in my specific case, but only because `uniq -c`'s output pads numbers with leading spaces for alignment — the space-padding coincidentally made string comparison behave like numeric comparison. This is fragile, not a real guarantee — always use `-n` explicitly for numeric data rather than relying on incidental formatting.
