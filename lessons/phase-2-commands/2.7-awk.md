# 2.7 — awk

## What I learned

`awk` treats each line as a row automatically split into fields by whitespace (`$1`, `$2`, etc.; `$0` = whole line). Unlike `cut`, it treats any number of consecutive spaces as a single separator — so inconsistent column padding (like in `ps aux`) doesn't break it.

```bash
awk '{print $1}' filename         # print field 1
awk '{print $1, $3}' filename      # print multiple fields
awk -F':' '{print $1}' filename    # custom delimiter, like cut's -d
awk '$4 > 1.0 {print $1, $2, $4}' filename   # filter by condition, then print
```

Used `ps aux | awk '$4 > 1.0 {print $1, $2, $4, $11}'` to find high-memory processes — confirmed VS Code Server's Node processes are consistently the top memory users on my machine, matching what I'd already noticed informally in Phase 1.

**UID filtering on /etc/passwd** — learned the real convention: UID 0 = root, UID 1–999 = system/service accounts (some dynamically assigned in that range, not always low fixed numbers), UID 1000+ = real human accounts. My first attempt (`$3 > 100`) let through several dynamically-assigned service accounts in the 900s because 100 wasn't the right boundary. Corrected to `$3 >= 1000`, which correctly isolated real accounts — though `nobody` (UID 65534) also appears, since it's a deliberately unprivileged placeholder account traditionally given a very high UID to avoid collisions, not a real human user.

## Real DevOps use
Exactly this kind of UID-based filtering is how account-management/security-audit scripts programmatically separate real user accounts from system infrastructure accounts on a server.
