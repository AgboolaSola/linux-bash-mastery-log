# 2.6 — sed (stream editor)

## What I learned

`sed` reads text line by line and applies transformations — most commonly find-and-replace — without opening an editor.

```bash
sed 's/find/replace/' filename       # prints result to screen, does NOT modify the file
sed -i 's/find/replace/' filename    # -i = in-place, actually modifies the file
sed -i.bak 's/find/replace/' filename # in-place, but keeps a .bak backup of the original first
```

Syntax needs three slashes total (`s/find/replace/`) — missed the closing slash on my first attempt and got `unterminated 's' command`, a genuinely common typo-driven error.

Tested `-i.bak`: confirmed the original file changed correctly, and a `.bak` copy with the pre-change content was created alongside it — a safety net against accidental bad substitutions, since `-i` alone has no undo.

## Real DevOps use
Changing a config value (e.g. `debug=true` → `debug=false`) across many files/servers in one line, instead of manually opening each one.
