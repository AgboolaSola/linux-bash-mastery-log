# 2.8 — df, du, free

## What I learned

```bash
df -h                              # disk usage per mounted filesystem, human-readable
du -sh /path                        # total size of a specific folder
free -h                             # RAM usage
```

Ran on my own machine: root filesystem (`/dev/sdd`) at 1% used — very healthy. `/mnt/c` (Windows drive) separately at 47% — confirms again that it's genuinely separate storage from Linux's own filesystem.

`du -sh /var/log/` hit real permission errors on `root`-owned subfolders (`chrony`, `private`) — couldn't see inside them as `sola`, but still returned a total for everything accessible. To see everything including restricted folders, need `sudo du -sh /path`.

`free -h`: "available" memory is more meaningful than "free" — accounts for cache that can be reclaimed instantly if needed, not just literally-untouched RAM.

## Real DevOps use
Classic two-step diagnostic: `df -h` finds which filesystem is full, `du -sh /path/*` narrows down which specific folder is the cause.
